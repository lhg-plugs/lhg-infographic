# lhg-ig-review：手机端可读性评审

> 目标：确保这张图在手机上有人愿意看、看得懂、记得住。
> 核心纪律：**blocker 清零才许交付**。评审不是挑刺，是交付前的最后一道门。

## 1. 何时使用

- 图已画完、准备发布前 → 跑完整流程（脚本 + 人工四项）
- 拿到一张别人做的图想评审时 → 先跑脚本定位硬伤，再人工看
- 只想快速看一眼有没有硬伤时 → 只跑第 3 步脚本

## 2. 输入与输出

- **输入**：信息图项目目录（含 `chart-spec.json` + `output/` 产物）
- **输出**：`docs/audit-YYYYMMDD.md` 评审报告，结论只能是"可交付"或"返工"

## 3. 第一步：跑确定性脚本（必做）

```bash
python3 scripts/audit/infographic_audit.py --target <项目目录> --format text
```

16 条规则分五类，脚本零第三方依赖、秒级出结果：

### 3.1 标题与来源（2 条）
| 规则 | 级别 | 抓什么 |
|---|---|---|
| IG-TITLE-001 | blocker | 标题缺失或过短（< 4 字）——没标题的图不许交付 |
| IG-SOURCE-001 | warning | 数据来源未标注——没来源的图就是一张漂亮的谣言 |

### 3.2 数据-图表映射（5 条）
| 规则 | 级别 | 抓什么 |
|---|---|---|
| IG-MAP-001 | blocker | 饼图表达时间趋势（扇形表达不了先后） |
| IG-MAP-002 | blocker | 折线图画无序分类（斜率暗示了不存在的连续变化） |
| IG-MAP-003 | warning | 饼图扇区 > 6（色块拼盘，看不出重点） |
| IG-MAP-004 | warning | 柱状图类别 > 12（手机上缩成牙签） |
| IG-MAP-005 | warning | 柱状图 Y 轴不从 0 起且未标注截断（条形长度撒谎） |

### 3.3 字号（2 条）
| 规则 | 级别 | 抓什么 |
|---|---|---|
| IG-FONT-001 | blocker | 最小字号 < 20px（750px 基准，手机上看不清） |
| IG-FONT-002 | warning | 标题字号 ≤ 标签字号（视觉层级塌掉） |

### 3.4 颜色（2 条）
| 规则 | 级别 | 抓什么 |
|---|---|---|
| IG-COLOR-001 | warning/blocker | 文字/背景对比度 < 4.5 警告、< 3.0 blocker（WCAG 2.x 公开公式） |
| IG-COLOR-002 | warning | 相邻系列色对比度 < 1.3（肉眼分不开） |

### 3.5 数据（5 条）
| 规则 | 级别 | 抓什么 |
|---|---|---|
| IG-DATA-001 | blocker | 数据为空——空数据画什么图 |
| IG-DATA-002 | blocker | 标签与数值数量不匹配/缺字段 |
| IG-DATA-003 | warning | 饼图百分比总和 ≠ 100（数据自相矛盾） |
| IG-LABEL-001 | warning | 折线/柱状图缺坐标轴标签 |
| IG-UNIT-001 | nit | 数值大但单位未声明 |

阈值说明：字号阈值以 750px 设计稿为基准（手机竖屏信息图的主流宽度）；对比度公式采用 WCAG 2.x 相对亮度定义（公开标准）。阈值调整必须记录在评审报告里，不许悄悄放水。

## 4. 第二步：人工四项（脚本抓不到的）

1. **手机实看**：把图缩到 375px 宽看——标题一眼读清吗？关键数字看得见吗？看不清就返工字号，不要信电脑大屏上的感觉。
2. **遮图例看颜色**：遮住图例和文字，只看色块——几个系列分得开吗？红绿配色直接判死刑（色盲用户）。
3. **来源三要素**：数据来源、统计口径、时间范围，三个齐了吗？缺一个都是 warning 起步。
4. **信息量控制**：数一下"想让人记住的点"——超过 3 个就拆图。一张图只讲一件事，这是铁律。

## 5. 第三步：输出评审报告

存为 `docs/audit-YYYYMMDD.md`：扫描范围、blocker/warning/nit 数量、逐条返工清单（映射错误优先）、人工四项结论、最终结论（"可交付"/"返工"）。

豁免规则：warning 可豁免但必须写理由；blocker 不许豁免。IG-MAP-001/002 是方向性错误：修法是换图表类型，不是调参数。

## 6. 反模式（这些做法一定翻车）

- **只在电脑大屏上看**：电脑上 24px 的字很清楚，手机上就是蚂蚁——评审必须在手机宽度下做。
- **为清零改规则**：把字号阈值调低让报告变绿是作弊。
- **映射错误调参数**：饼图画趋势，调颜色、调字号都救不了——换折线图。
- **来源"下次再补"**：没来源的图发出去就是你的责任，补了来源再发。
- **评审报告不存档**：口头"改完了"等于没改，报告是交付物的一部分。

## 7. 自检与反馈

质检门（评审流程自身的质检）：

- [ ] 脚本 16 条规则全跑完（summary 里 rules_run=16）
- [ ] blocker 为零（warning 豁免有书面理由）
- [ ] 人工四项每项有书面结论
- [ ] 评审报告已存档到 `docs/`
- [ ] 返工后重跑脚本确认清零

标准冒烟用例：`fixtures/info-bad` 必须检出 blocker（含 IG-TITLE-001 与 IG-MAP-001），`fixtures/info-good` 必须零 blocker。

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-infographic/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。

## 9. 附：高频误报与处理

- **IG-COLOR-002 误报**：装饰性色块（如背景渐变）被计入系列色——spec 的 `series` 只放数据系列颜色，装饰色不要放进去。
- **IG-FONT-001 误报**：图注/页脚小字——小于 20px 的文字如果不是数据标签，移到"解读区"或删掉；数据标签必须 ≥ 20px。
- **IG-DATA-003 误报**：饼图 value 不是百分比而是绝对值——此时应先换算成百分比再画饼图，或改用条形图；规则按"饼图即占比"假设报警是正确的。

## 10. 附：发布前最后一分钟检查

- [ ] 手机宽度下看一遍（375px，不是电脑大屏）
- [ ] 标题是一句人话（不是"数据图"）
- [ ] 来源三要素在图上找得到
- [ ] 关键数字一眼可见（不需要眯眼）
- [ ] 转发给一个人看，问他"这张图想说什么"——答对了才发
