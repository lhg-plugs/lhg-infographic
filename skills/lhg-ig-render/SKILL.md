# lhg-ig-render：Canvas 确定性绘制规范

> 目标：把 `chart-spec.json` 变成一张手机端可读的长图，同样的 spec 每次画出来一模一样。
> 核心纪律：**所有视觉参数只从 spec 取**。尺寸、颜色、字号不许硬编码"看着差不多"的值。

## 1. 何时使用

- `chart-spec.json` 的选型已用户确认，要出图时 → 跑本 skill
- spec 缺字段时 → 先回去补 spec，不许边画边猜
- 图已画完想调样式时 → 改 spec 重跑，不要手改产物

## 2. 输入与输出

- **输入**：已确认的 `chart-spec.json`
- **输出**：`output/<名>.html`（Canvas 2D 绘制，可直接在浏览器打开截图/打印）

## 3. 第一步：读 spec（校验先行）

绘制前先校验 spec 完整性，缺字段就停：

- 必填：`title`、`chart_type`、`data`（非空）、`fonts`、`colors`、`source`
- 折线/柱状图必填：`x_label`、`y_label`
- 建议：`width`（默认 750）、`unit`、`y_starts_at_zero`（柱状图默认 true）

## 4. 第二步：五段式布局

750px 宽画布从上到下五段，顺序固定：

1. **标题区**（高约 120px）：`title`，字号 `fonts.title`，居左，加粗。标题必须是一句人话（如"第三季度销量逐月上涨"），不许是"销量数据图"这种废话标题。
2. **副标题/口径区**（高约 50px）：时间范围、统计口径，一行小字。
3. **图表区**（高约 450px）：按 `chart_type` 绘制，坐标轴标签、刻度、单位齐全。
4. **解读区**（可选，高约 120px）：1-3 个要点（bullet），帮读者抓住核心信息。不许超过 3 条。
5. **来源区**（高约 60px）：`source`（数据来源三要素：来源/口径/时间），字号可小但必须清晰可读。

边距：左右各留 40px，元素之间留白 ≥ 30px——拥挤是信息图的第一杀手。

## 5. 第三步：字号规范（750px 基准）

| 元素 | 建议字号 | 最小值（硬门） |
|---|---|---|
| 标题 `fonts.title` | 36px | 28px |
| 图表标签 `fonts.label` | 28px | 24px |
| 刻度/来源 `fonts.tick` | 24px | 20px |

层级规则：`title` > `label` > `tick`，三级字号必须拉开差距（至少差 4px），否则视觉层级塌掉。最小值是审计脚本 IG-FONT-001 的硬门：`tick` < 20px 直接 blocker。

## 6. 第四步：颜色规范

1. **文字/背景对比度**：正文文字与背景对比度 ≥ 4.5（WCAG 2.x 公开标准公式），达不到就加深文字或调浅背景——这是硬门，不是建议。
2. **系列色**：相邻系列色必须肉眼可分（对比度 ≥ 1.3）；色盲友好——不许用红绿搭配区分关键系列。
3. **颜色数量**：单张图系列色 ≤ 4 种，多了就分组或拆图。
4. **背景**：默认白底或浅底，深色背景必须全套重调对比度，不许只换个背景色就交差。

## 7. 第五步：按类型绘制要点

- **折线图（line）**：线宽 ≥ 4px；数据点画圆点标记；Y 轴从 0 起（不从 0 起必须标注"Y 轴截断"）；面积填充用浅色，不许喧宾夺主。
- **柱状图（bar）**：Y 轴必须从 0 起（条形长度代表数值，这是铁律）；柱宽一致、间距一致；类别 > 12 个就横向排或聚合。
- **饼图/环形图（pie）**：扇区 ≤ 6 个；每个扇区直接标百分比（不许只靠图例猜）；最小扇区 < 5% 就合并为"其他"。
- **散点图（scatter）**：坐标轴标签 + 单位必须有；趋势线可选，不许用趋势线暗示因果。

## 8. 第六步：输出与一致性

1. 输出 `output/<名>.html`：单文件，Canvas 绘制，打开即所见即所得。
2. 确定性验证：同一 spec 跑两遍，截图做像素对比——必须一致（随机种子、时间戳不许进图）。
3. 绘制脚本不许读 spec 之外的数据；图里的每个数字必须能在 spec 的 `data` 里找到。

## 9. 反模式（这些做法一定翻车）

- **边画边猜**：spec 缺 `y_label`，绘制时随手写一个——猜的标注就是错的标注。
- **字号"看着差不多"**：设计师的"差不多"在手机上就是"看不清"，字号只从 spec 取。
- **深色文字浅色底反过来**：深底浅字整套对比度要重算，不许直接反色。
- **3D 效果**：Canvas 的阴影/渐变玩得越花，数据失真越严重——扁平、干净、准确。
- **图例代替直接标注**：读者在图例和扇区间来回对颜色，体验极差——能直接标就直接标。
- **输出 PNG 就删 HTML**：HTML 是可复现的源，PNG 只是截图——源文件必须保留。

## 10. 自检与反馈

质检门（出图前自查）：

- [ ] 五段式布局齐全（标题/口径/图表/解读/来源，解读可空但来源不可空）
- [ ] 三级字号 ≥ 最小值且层级分明
- [ ] 文字/背景对比度 ≥ 4.5，系列色可分
- [ ] 坐标轴标签、单位齐全（折线/柱状）
- [ ] 同一 spec 跑两遍像素一致
- [ ] 审计脚本 IG-FONT/IG-COLOR 零 blocker

标准冒烟用例：用 `fixtures/info-good/chart-spec.json` 绘制——手机宽度下标题、数字、来源全部清晰可读。

## 11. 附：绘制代码骨架（伪代码，任何 Canvas 实现照此填）

```
读取 chart-spec.json → spec
校验必填字段（缺字段则报错退出，不许边画边猜）

画布 = 新建 Canvas(spec.width || 750, 高度按五段累加)
y = 上边距

绘制标题区：文字(spec.title, 字号=spec.fonts.title, 加粗, 居左)
y += 120
绘制口径区：文字(时间范围+口径, 字号=spec.fonts.tick, 灰色)
y += 50

按 spec.chart_type 分发：
  line    → 画坐标轴(x_label/y_label) + 折线(线宽≥4px) + 数据点圆点
  bar     → 画坐标轴(Y轴从0起) + 等宽柱子 + 数值标注
  pie     → 画扇形(≤6个) + 每个扇区直接标百分比
  scatter → 画坐标轴 + 散点
y += 450

绘制来源区：文字("数据来源："+spec.source, 字号=spec.fonts.tick)
输出 output/<名>.html
```

关键约束：所有数字/颜色/字号只从 spec 取；同一 spec 跑两遍输出必须一致（不许用随机数、时间戳）。

## 12. 附：常见绘制事故

- **中文乱码**：Canvas 字体栈必须带中文字体（如 "PingFang SC, Microsoft YaHei, sans-serif"），否则部分环境显示方框。
- **高清屏模糊**：Canvas 实际像素 = 逻辑像素 × devicePixelRatio，不处理就是糊的。
- **长标题溢出**：标题超过画布宽要自动换行或缩小字号，不许画出边界。
- **颜色写死**：把 "#1f77b4" 写死在代码里而不是读 spec.colors——换主题时全崩。
- **小数位数**：百分比保留 1 位小数，金额按单位取整——满屏 33.333333% 是事故。

## 13. 附：字号颜色速查卡（750px 基准，贴显示器上）

```
字号：标题 36 / 标签 28 / 刻度来源 24（最小 20，硬门）
层级：title > label > tick，至少差 4px
对比：文字/背景 ≥ 4.5（< 3.0 直接 blocker）
系列色：相邻可分（≥1.3），≤ 4 种，禁红绿搭配
边距：左右 40px，元素间距 ≥ 30px
线宽：折线 ≥ 4px
```

## 14. 附：一句话速记

同样的 spec，跑一百遍，出一百张一模一样的图——这叫确定性绘制。凡是"看着差不多"的地方，都是未来的事故。
