# lhg-ig-chart：图表选型决策树

> 目标：为这组数据选出唯一正确的图表类型，并能说出"为什么不用别的"。
> 核心纪律：**先选型再绘制**。图表类型错了，画得再好看也是错的。

## 1. 何时使用

- 数据已整理干净，要决定"用什么图"时 → 跑本 skill
- 用户说"随便画个好看的"时 → 更要跑本 skill（"好看"是结果，不是选型标准）
- 图已画完想换类型时 → 回到本 skill 重新走决策树，不要在原图上硬改

## 2. 输入与输出

- **输入**：干净数据（`[{"label","value"}]`）+ 核心信息一句话
- **输出**：选型卡（数据特征 / 主选图表 / 备选图表 / 排除项与理由），写入 `chart-spec.json` 的 `chart_type` + `data_shape`

## 3. 第一步：判定数据特征（data_shape）

先看数据回答"你在表达什么关系"，五选一：

| data_shape | 定义 | 例子 |
|---|---|---|
| `time_series` | 随时间变化的趋势 | 月度销量、历年营收 |
| `part_of_whole` | 整体中的构成占比 | 市场份额、预算分配 |
| `categorical_nominal` | 无序分类的比较 | 各城市销量、各产品评分 |
| `categorical_ordinal` | 有序分类的比较 | 年龄段、满意度等级 |
| `scatter_xy` | 两个变量的关系 | 广告投入 vs 销量 |

判定技巧：看 label——是时间（7月/8月/2024）就是 time_series；是名称（北京/上海）就是分类；加起来约等于 100% 就是 part_of_whole。

## 4. 第二步：走决策树（特征 → 图表）

```
time_series → 折线图（line）
  └─ 数据点 > 20？→ 聚合（按周→按月）或只画关键区间

part_of_whole →
  ├─ 类别 ≤ 6 → 饼图/环形图（pie）
  └─ 类别 > 6 → 横向条形图（bar），或合并小类为"其他"

categorical_nominal → 柱状图（bar），按数值从大到小排
categorical_ordinal → 柱状图（bar），按自然顺序排（不许按数值重排！）
scatter_xy → 散点图（scatter）
```

一个主选 + 一个备选：主选是最不会错的，备选是"核心信息特殊时更好"的（如想强调"第一名遥遥领先"时，柱状图比折线图好）。

## 5. 第三步：排除项（说出为什么不用）

选型卡必须写清楚"排除了什么、为什么"，这是选型的专业度证明：

- **饼图画趋势**：扇形表达不了时间先后，看到"各月占比饼图"直接判死刑。
- **折线画无序分类**：折线的斜率暗示连续变化，"北京-上海-广州"的折线毫无意义。
- **3D/立体图表**：3D 饼图的前扇形视觉面积大于实际占比，这是视觉欺诈，一律不用。
- **双 Y 轴**：两个量级不同的指标硬画一张图，读者一定会读错——拆成两张图。
- **雷达图**：超过 5 个维度就是一团乱麻，且面积误导性强，非必要不用。

## 6. 第四步：用户拍板与写入

选型是方向性决策，必须用户确认。把选型卡（含排除理由）交给用户，一句话确认后写入 `chart-spec.json`。用户推翻选型时：回到第 3 步重走，不要在绘制阶段偷偷换类型。

## 7. 反模式（这些做法一定翻车）

- **为好看选图**："饼图好看"不是选型理由，数据特征才是。
- **一张图讲两件事**：趋势和构成塞一张图，读者两句都记不住——拆图。
- **有序分类按数值重排**："非常满意→非常不满意"被排成"满意→非常满意→一般"，顺序一乱，趋势全错。
- **类别太多硬画饼图**：12 个扇形的饼图就是色块拼盘，合并小类或换条形图。
- **选型不写理由**：三个月后没人记得为什么选这个图，选型卡是项目的记忆。

## 8. 附：选型速查表

| 我想表达… | 数据特征 | 用这个图 | 千万别用 |
|---|---|---|---|
| 销量涨没涨 | time_series | 折线图 | 饼图 |
| 谁占多少 | part_of_whole（≤6类） | 饼图/环形图 | 折线图 |
| 谁占多少（>6类） | part_of_whole | 横向条形图 | 饼图 |
| 哪个最高 | categorical_nominal | 柱状图（降序） | 折线图 |
| 满意度分布 | categorical_ordinal | 柱状图（自然序） | 打乱排序的柱状图 |
| 投入产出关系 | scatter_xy | 散点图 | 折线图 |
| 目标完成率 | 单值+目标 | 子弹图/进度条 | 饼图 |

## 9. 自检与反馈

质检门（选型交付前自查）：

- [ ] `data_shape` 判定有依据（label 特征写得出来）
- [ ] 主选图表符合决策树映射
- [ ] 排除项写了理由（至少 2 条"为什么不用"）
- [ ] 一张图只讲一件事（核心信息一句话能对应上）
- [ ] 用户已拍板，`chart-spec.json` 已写入

标准冒烟用例：时间序列数据 → 必须选出 line；8 类构成数据 → 必须选出 bar（而非 pie）并写出"饼图扇区过多"的排除理由。

发现 bug 或有改进建议，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-infographic/issues，正文写清"复现步骤 → 实际表现 → 期望表现"。

## 10. 附：真实翻车案例库（举一反三）

### 10.1 饼图画趋势
- 翻车：一张"各月销量占比"饼图，12 个扇形，标题写"销量持续增长"。
- 问题：饼图没有时间方向，"增长"二字在图上完全看不出来；12 个扇形谁也分不清。
- 正解：折线图，横轴月份，趋势一目了然。

### 10.2 折线画无序分类
- 翻车："各城市满意度"折线图，北京 90、上海 85、广州 88 连成线。
- 问题：折线的上下起伏暗示"从北京到上海下降了"，但城市之间没有顺序关系，斜率毫无意义。
- 正解：柱状图，按数值降序排。

### 10.3 Y 轴不从 0 起的柱状图
- 翻车：两家公司营收 100 亿 vs 105 亿，Y 轴从 90 起画，后者柱子高 5 倍。
- 问题：条形长度代表数值，Y 轴截断就是视觉欺诈。
- 正解：Y 轴从 0 起；差距小就换文字说明，不要靠截断制造"巨大差距"。

### 10.4 双 Y 轴的灾难
- 翻车：左轴销量（万件）、右轴单价（元），两条线"交叉"得出"量价齐升"结论。
- 问题：双轴的交叉点完全取决于坐标轴范围设定，换个范围结论就反了。
- 正解：拆成两张图，或只讲一个指标。

### 10.5 3D 饼图的面积骗局
- 翻车：3D 饼图里前排 25% 的扇形看起来比后排 30% 还大。
- 问题：透视让前排扇形视觉面积膨胀，数据被视觉效果篡改。
- 正解：永远用扁平 2D 饼图；扇区 > 6 就换条形图。

## 11. 附：选型决策记录模板

```markdown
## 选型卡（YYYY-MM-DD）

- 数据特征：time_series（label 为 2024-01 至 2024-12）
- 核心信息：下半年销量明显加速
- 主选：折线图（line）——趋势表达最直接
- 备选：柱状图（bar）——如需强调单月绝对值可切换
- 排除：饼图（扇形表达不了时间先后）；面积图（单系列不需要填充）
- 用户确认：已确认（2026-10-11）
```
